# CupFlow 数据来源与合规说明

## 1. 适用范围

CupFlow 面向饮品门店的制作辅助场景：店长端扫描或录入订单、向眼镜端下发单杯制作任务；眼镜端以提示、语音和视觉核验辅助店员完成配方步骤，并把异常片段回传至门店端复核。本说明覆盖演示及后续门店试用的最小数据处理范围。

## 2. 数据清单、来源与授权状态

| 数据类型 | 典型字段/内容 | 来源 | 授权与用途 |
| --- | --- | --- | --- |
| 订单与配方 | 订单号、饮品名、规格、加料、步骤 | 店长扫描杯贴、人工录入、POS 对接接口（预留） | 门店对其业务数据享有管理权限；仅用于订单下发与制作提示 |
| 配料格架配置 | 格数、格位名称、基准照片 | 店长主动配置与拍摄 | 由门店负责人录入；用于辅助判断小料位置，不作为唯一判定依据 |
| 眼镜画面 | 制作台局部画面、杯具/物料/操作帧 | 佩戴者在任务期间主动开启设备 | 仅限任务核验、异常复盘与调试；应避免采集非工作区域、顾客面部和无关人员 |
| 异常记录 | 时间、订单号、饮品名、操作者名称、前后关键帧 | 视觉或操作流程触发 | 仅用于当前门店的质量复核；操作者名称应使用门店内部代号或经告知后的姓名 |
| 运行诊断 | 连接状态、服务错误码、版本号 | 本地设备运行日志 | 用于排障；不得写入订单全文、图片原帧或密钥 |

演示用配方、杯贴样张与格架照片均由项目团队或门店试用方自行制作、拍摄或提供；第三方 POS、顾客订单及真实门店视频接入前，应由部署主体取得相应系统权限与现场告知/同意。

## 3. 最小化、脱敏与保存

1. **最小采集**：只在开始制作后采集制作台局部；空闲时不保留连续录像。
2. **异常留存最小化**：异常仅保存触发点前后约 2 秒的关键帧，并按“时间 + 订单号 + 饮品名 + 操作者代号”归档；不把整段长视频作为默认留存。
3. **订单最小化**：演示和调试可用测试订单号；接入真实订单时不采集手机号、支付信息、地址等与制作无关字段。
4. **脱敏与访问**：导出前对订单号进行遮盖或替换；异常记录仅由被授权的店长/质控人员访问，不得用于与制作无关的考勤、画像或传播。
5. **保存与删除**：本地异常素材和测试记录由门店配置保存周期；达到周期后由门店负责人删除。项目默认不建立跨门店集中素材库。

## 4. 模型与外部服务边界

视觉识别调用配置的视觉模型服务，仅发送实现当前识别所需的压缩图像与任务文本；密钥仅保存在服务端环境变量，不写入移动端安装包、仓库或提交材料。若部署方替换模型/接口，应重新评估其数据处理条款、传输范围和地域要求。

CupFlow 的视觉判断是**制作辅助信号**，不是食品安全、配方合规或经营决策的最终结论。低置信度、遮挡、光照变化、无基准图或出现未注册物料时，系统应提示“待人工确认”，不应自动将异常结论写为事实。

## 5. 食品安全、员工隐私与人工确认边界

| 事项 | 系统边界 | 人工责任 |
| --- | --- | --- |
| 食品安全 | 提示可能漏加/错加/步骤异常，不替代卫生、保质期、过敏原与成品安全检查 | 店员按门店 SOP 制作；店长/食品安全负责人作最终确认 |
| 配方与订单 | 按已授权配方和订单字段生成提示 | 店长确认配方版本、订单内容与例外需求 |
| 视觉识别 | 以置信度和格架/标签等上下文给出辅助判断 | 遇到低置信度、遮挡、异常提示时，由店员纠正或跳过并留痕 |
| 员工隐私 | 只处理任务必要画面和代号，限制查看与导出 | 部署前告知佩戴者和现场人员拍摄范围、保存期限及申诉渠道 |
| 顾客隐私 | 不以顾客为识别对象，不采集顾客敏感信息 | 门店避免镜头覆盖收银区/顾客等候区；真实订单接入时落实内部权限控制 |

## 6. 部署主体与接口责任

门店或其授权技术服务方是本地部署、账号权限、设备管理和数据删除的责任主体。POS 接入采用“门店授权的订单接口/导出文件 → 字段映射 → 店长端确认下发”的方式；在未完成接口授权、字段校验和异常回退设计前，不自动写回 POS，也不更改订单状态。对外部系统的访问令牌由部署方管理并定期轮换。

## 7. 试用前检查

- 明确摄像头可见范围，仅覆盖制作台。
- 使用测试订单完成一次端到端联调，再接入真实订单。
- 配置异常素材保存周期、店长账号和导出权限。
- 向佩戴店员说明启动/停止方式、异常记录方式和人工跳过的留痕规则。
- 记录模型服务、POS 接口和设备版本；发生异常时优先停止自动流转并人工接管。

> 本说明是项目的产品与工程边界说明，不构成法律意见。实际部署应结合门店所在地适用法律、集团制度、供应商协议及现场管理要求复核。
