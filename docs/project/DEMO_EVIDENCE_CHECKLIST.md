# CupFlow Demo 运行与验证清单

## 一条可验证的单订单任务链

1. 店长端扫描或录入杯贴订单，确认订单号、饮品、加料与配方。
2. 店长端选择已连接眼镜并下发订单；眼镜端收到订单后显示首个步骤。
3. 店员通过点击或语音开始制作。视觉服务以当前步骤、配方、格架配置和现场画面作为判断上下文。
4. 系统完成步骤后自动进入下一步；低置信度或不符合预期时，眼镜端显示/播报“步骤错误”，店员纠正后继续，或轻触跳过并写入异常记录。
5. 完成封装和杯贴检查后，眼镜端回传完成状态；店长端同步更新订单。
6. 打开异常管理，核对异常记录的时间、订单、饮品、操作者代号与前后关键帧。

## 运行证据建议

- 店长端：已连接状态、订单详情、下发成功、完成状态和异常记录。
- 眼镜端：必要的当前步骤字幕、错误提示、语音播报/轻触回退或跳过。
- 工具调用：视觉服务状态、视觉核验结果、配方/格架知识配置生效。
- 效果验证：用同一订单先制造一次错加/漏加，再纠正并完成；在用户反馈与量化表中留存人工核验结果。

## 本地运行入口

- Web/本地服务：参见项目根目录 `README.md` 与 `docs/project/RUNBOOK.md`。
- Android 构建：`android-native` 下执行 Gradle Debug 构建；店长端包为 `companion-debug.apk`，眼镜端包为 `app-debug.apk`。
- USB 联调：使用 ADB 连接眼镜，通过 `adb reverse tcp:3000 tcp:3000` 让眼镜访问本机视觉服务；具体命令见 `RUNBOOK.md`。

## 验证边界

- 系统只提供辅助判断；配方、食品安全和异常结论均须由店员/店长人工确认。
- 当视觉服务不可用、连接断开或识别置信度不足时，应以明确错误提示和人工操作为回退，不将任务误标为已完成。
