# CupFlow 多订单多人派单模块设计

## 目标

为 CupFlow 增加一个可独立调用的订单派单模块，支持半自动与自动两种模式。该模块为未来 KDS 与员工端接入提供稳定接口，但本期不新增多人演示界面，不改变现有 A102 单订单 Demo。

## 范围

### 包含

- 内存订单队列、员工工作状态与派单 Trace。
- 半自动模式：返回推荐员工，不改变订单归属。
- 自动模式：仅向没有进行中订单的在线员工派送。
- 空闲优先、技能匹配、等待时长优先的确定性策略。
- 订单锁与幂等检查，避免同一订单被重复派送。
- 模拟评测接口与 API 文档。

### 不包含

- 多人派单 UI、录像脚本或现有 Demo 页面改造。
- 真实 KDS/POS、员工账号、角色权限系统、数据库与跨浏览器实时同步。
- 实体眼镜 SDK。

## 数据模型

- `Worker`：员工 ID、姓名、在线状态、当前订单数、技能标签。
- `DispatchOrder`：订单 ID、饮品、优先级、创建时间、所需技能、状态与被分配员工。
- `DispatchTrace`：Trace ID、模式、候选员工、推荐/派送结果、依据与时间。

## 分配策略

1. 仅考虑在线且 `activeOrderCount = 0` 的员工。
2. 优先选择技能覆盖订单所需技能的员工。
3. 在同等技能下选择空闲时间更长、负载更低的员工。
4. 自动模式以原子化内存锁标记订单；已分配订单直接返回原分配结果。
5. 半自动模式只产生候选建议，必须由调用方在后续接口确认。

## API

- `GET /api/dispatch/state`：读取模拟队列、员工与最近 Trace。
- `POST /api/dispatch/recommend`：半自动推荐或自动派单。
- `POST /api/dispatch/complete`：将订单标记完成并释放员工。
- `GET /api/dispatch/evaluate`：运行派单策略验证。

## 验收

- 自动模式不会向忙碌员工派单。
- 半自动模式不会修改订单状态。
- 重复调用自动派单不会造成重复分配。
- 所有派单结果带有可读依据与 Trace。
- 现有单订单 Agent 构建和策略评测不受影响。
