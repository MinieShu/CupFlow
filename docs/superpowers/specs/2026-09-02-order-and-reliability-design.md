# CupFlow 订单接入与可靠性设计

## 目标

在不改变单眼镜、单订单制作闭环的前提下，补足可导入的订单入口、可解释决策记录和安全恢复状态。

## 范围

1. 店长端提供 JSON 订单导入入口。订单结构为 `id`、`drink` 和可选 `options`；解析失败不改变当前订单，解析成功后由店长确认下发。
2. 手机端记录每次杯贴/操作识别的时间、订单、步骤、事件、置信度、来源、理由、耗时与处理结果；提供只读日志页。
3. 手机端独立展示眼镜连接、关键帧、视觉服务和自动识别状态。视觉调用失败时停止自动识别，不推进步骤；重新建立眼镜连接或重新下发订单后可恢复。

## 非目标

- 不绑定特定 POS 厂商或写入第三方订单系统。
- 不上传日志、异常帧或个人数据到新的云端服务。
- 不改变配方、格架与异常证据的既有逻辑。

## 验收

- 有效 JSON 可生成订单预览并下发；无效 JSON 显示错误且不覆盖当前订单。
- 每次视觉判断都会产生本地日志，日志能区分推进、异常、等待与服务失败。
- 服务失败或眼镜连接中断时，当前步骤不变化；状态页给出恢复入口。
